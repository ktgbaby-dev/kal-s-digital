# Kal’s Digital website: architecture

Last updated 30 October 2026. Branch `redesign-2026` of `ktgbaby-dev/kal-s-digital`.

## 1. Technology stack

| Layer | Choice | Why |
|---|---|---|
| Pages | Hand-written static HTML, one file per page | Matches the existing repo and every other Kal’s Digital site; fastest possible delivery; no framework to maintain |
| Styles | One stylesheet, `assets/css/site.css`, built on CSS custom properties (design tokens) | Tokens come straight from the brand guidelines |
| Behaviour | One dependency-free script, `assets/js/site.js` (about 12 KB) | Menu, header state, reveal-on-scroll, contact form. Every page works without it |
| Shared parts | `tools/build.py` (Python 3.10+, standard library) stamps the head, header, icon sprite and footer into every page from `partials/` and `site.json` | Keeps one source for navigation, SEO tags and the domain, without a build pipeline on Vercel |
| Contact API | `api/contact.js`, a Vercel Node.js function with no dependencies | Sends enquiries by email through Resend once configured; otherwise the page uses WhatsApp |
| Fonts | Self-hosted WOFF2 from the brand kit (Outfit, Instrument Serif, DM Sans, DM Mono) | No third-party requests; the brand’s exact faces |
| Hosting | Vercel project `kal-s-digital`, static files plus one function | Already exists and is linked to the repo |

The old one-page site (GSAP from a CDN, Google Fonts, graphite and bronze palette, `mailto:` form) was replaced. GSAP and Google Fonts were dropped: the new motion needs about 30 lines of JavaScript and the fonts are now local. The old copy’s structure (Problem → How we think → What we build → Diagnose/Design/Build/Refine → Founder → Contact) informed the new home page, and the four process stages were kept.

## 4. Shared components

All defined in `assets/css/site.css`:

- **Header**: sticky, Paper background, primary lockup, six links, “Start a project” button. Under 1100 px it becomes a Menu button that opens a full-screen panel (focus moves in, the rest of the page is `inert`, Escape closes and returns focus).
- **Footer**: Ink, white-on-ink lockup, three link columns, the official sign-off, copyright and privacy link, with a Kal’s Weave band on its top edge.
- **Buttons**: primary (Olive), secondary (outline), light and ghost-light for dark panels. 48 px tall, 6 px radius.
- **Labels**: DM Mono, uppercase, +0.16em tracking, with a diamond marker.
- **Diamond list**, **feature list**, **service list**, **capability rows**, **process steps**, **flow steps**, **FAQ** (native `details`), **chips** (pills, the only rounded shapes).
- **Device frames**: browser frame showing the real URL, phone frame, and a scrollable full-page preview (`.page-scroll`, keyboard-focusable). These are the only elements with shadows.
- **Kal’s Weave band**: `.weave-band` (48/64/96 px tall = 0.3× to 0.6× of the 160 px tile) with a slow drift that stops under reduced motion. Never behind text or the logo.

## 5. Design system

Tokens in `:root` of `site.css`:

- **Colour**: the eight official values (`--kd-olive #55692D`, `--kd-white`, `--kd-ink #1B2210`, `--kd-sage #A9BB83`, `--kd-olive-light`, `--kd-olive-pale`, `--kd-olive-mist`, `--kd-paper #F6F5EF`) plus the design-system tokens `--kd-ink-muted #5E6652`, `--kd-ink-raised`, `--kd-line`, `--kd-line-dark`. Olive is never used as text on Ink (sage is used instead). Context classes `.on-dark` and `.on-olive` switch label, emphasis and focus colours.
- **Type**: Outfit 600 for headings, product names and the Slotù text wordmark; Instrument Serif for display headlines with an italic closing phrase in Olive (Sage on Ink, Olive Pale on Olive); DM Sans 400/500 for body; DM Mono 500 for labels. Scale tokens `--fs-display-xxl` to `--fs-label`.
- **Spacing**: `--space-1` (4) to `--space-32` (128), section padding `--section-y`.
- **Layout**: 12-column grid (`.grid`, `.col-*`, `.start-*`), container 1280 px with `clamp(16px, 5vw, 64px)` gutters.
- **Radius**: 0 for panels, bands and logo tiles; 2 px inputs; 6 px cards, buttons and mockups; pill for chips only.
- **Rendering**: the home page’s later sections use `content-visibility: auto` (home only; it cut main-thread work there, and on shorter pages it confused automated contrast checks without a real gain). All six font faces are preloaded so the page is laid out once rather than once per late font.
- **Motion**: `--dur-fast/base/slow`, `--ease-out`. Reveal-on-scroll only hides content after the observer reports it is below the fold, so nothing can get stuck hidden; `prefers-reduced-motion` turns all motion off.
- **Breakpoints**: 480, 640, 768, 1024, 1100 (navigation), 1280.

Logos are the supplied master SVGs, used as images (never redrawn or recoloured). The horizontal lockup files include their clear space. Favicons use the official small-use K (solid diamond); app icons are exports of the official app-icon SVG.

## 7. Contact form architecture

```
contact/index.html ──GET /api/contact──▶ { email: true|false }
        │
        ├─ email: true  ──POST /api/contact (JSON)──▶ validate ─▶ Resend API ─▶ Kal’s Digital inbox
        │                                               │
        │                                               └─ 400 field errors / 429 / 502 / 503 shown honestly,
        │                                                  with a “send it on WhatsApp” fallback link
        └─ email: false, or no API (static preview)
                  └─ opens https://wa.me/2348088812532?text=<message>; status says nothing is sent
                     until the visitor presses send in WhatsApp
```

- The button text and the note under it change with the route, so the visitor always knows how the message travels.
- Validation runs in the browser and again on the server. Fields: name, business (optional), email, phone/WhatsApp (optional), interest (General digital services, KARD, Slotù, Something else), message. `?interest=kard|slotu|general|other` preselects the interest.
- Spam controls: hidden honeypot field, size limits, five messages per address per ten minutes (per function instance, best effort).
- The form posts with `method="post"`, so no form data ever lands in a URL on this site. Without JavaScript the function answers with a plain HTML page.
- **Separation from Slotù**: the endpoint has its own environment variables and never calls the Slotù portal, its `/api/enquiry`, inbox, Blob stores or keys.

## 9. Environment variables

Set on the `kal-s-digital` Vercel project only. Never commit values.

| Variable | Required | Purpose |
|---|---|---|
| `RESEND_API_KEY` | For email delivery | A Resend key created for this website only (not a client’s booking key) |
| `CONTACT_TO_EMAIL` | For email delivery | Inbox that receives enquiries |
| `CONTACT_FROM_EMAIL` | Optional | Verified sender. Defaults to Resend’s test sender, which can only deliver to the Resend account’s own address |

With either required variable missing, `GET /api/contact` returns `{ "email": false }` and the site uses WhatsApp.

## 10. Security headers

`vercel.json` sends a strict Content-Security-Policy (`default-src 'self'`, no inline scripts or styles), `X-Frame-Options: DENY`, `nosniff`, a strict referrer policy and a Permissions-Policy. Fonts are cached for a year; images for a day; the API is `no-store`.

## 11. Deployment requirements

Static files plus one Node.js function; no build command on Vercel (the committed HTML is already built). Run `python tools/build.py` before committing any change to `partials/`, `site.json`, `site.css` or `site.js` (it also refreshes cache-busting hashes). Full steps in `KALS_DIGITAL_DEPLOYMENT.md`.
